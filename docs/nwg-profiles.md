# Monitor Profiles (nwg-displays)

Monitor and workspace layout aren't hand-written — [`nwg-displays`](https://github.com/nwg-piotr/nwg-displays)
is a GUI for arranging monitors (position, resolution, refresh rate, scale,
rotation) that generates the Hyprland config for you and can save the result
as a named profile per machine/dock setup.

Launch it directly (`nwg-displays`); there's no keybind for it.

## Files

| File | Tracked? | What it is |
| --- | --- | --- |
| `hypr/monitors.lua`, `hypr/monitors.conf` | No | The active monitor layout, regenerated by nwg-displays every time you save |
| `hypr/workspaces.lua`, `hypr/workspaces.conf` | No | Workspace-to-monitor assignment for the active layout |
| `nwg-displays/active_profile.json` | No | Which saved profile is currently applied |
| `nwg-displays/profiles/*.json` | **Yes** | One file per saved profile — the portable, per-machine layout definitions |
| `nwg-displays/config` | **Yes** | nwg-displays' own app settings (view scale, snap threshold, etc.) |

The generated/active-state files are gitignored because they're regenerated
locally and specific to whatever's plugged in right now; the profile
definitions are tracked because they're what makes a layout portable across
machines and checkouts.

## Fresh checkout

`hyprland.lua` guards the `require` of `monitors.lua` (via
[`modules/lib/optional.lua`](../hyprland/dotfiles/.config/hypr/modules/lib/optional.lua))
so Hyprland still starts on a checkout that has never run nwg-displays — it
just shows a notification prompting you to run it and save a profile.

## Adding a profile for a new machine

1. Launch `nwg-displays` and arrange the monitors as you want them.
2. Save it as a new profile.
3. `git add hyprland/dotfiles/.config/nwg-displays/profiles/<name>.json` to
   track the new profile.
